====== OpenCloud Agenda – Entwicklung & Deployment ======

===== Übersicht =====

Das Projekt hat zwei Branches und drei Workflows:

^ Branch ^ Zweck ^
| ''dev'' | Entwicklung & Testen |
| ''main'' | Produktion & Releases |

^ Workflow ^ Trigger ^ Was passiert ^
| ''ci.yml'' | Push auf ''main'', Pull Requests | Build + Tests |
| ''deploy-dev.yml'' | Manuell (Forgejo UI) | Build + Deploy auf Server |
| ''release.yml'' | Git-Tag ''v*'' | Build + Release-ZIP auf Forgejo |

----

===== Tägliche Arbeit =====

==== 1. Auf dev-Branch arbeiten ====

Sicherstellen dass man auf ''dev'' ist:
<code bash>
git checkout dev
</code>

Änderungen machen, committen und pushen:
<code bash>
git add .
git commit -m "beschreibung"
git push
</code>

==== 2. Auf dem Server testen ====

In Forgejo: **Actions → Deploy Dev → Run workflow**

Der Workflow baut die App und deployt sie automatisch auf den Server.\\
Danach unter ''https://cloud.linux-nerds.org/apps/opencloud-agenda/'' prüfen.

==== 3. Alternativ: Lokal deployen (ohne Forgejo) ====

<code bash>
cd opencloud-agenda
bash deploy.sh
</code>

> **Hinweis:** Muss im eigenen Terminal ausgeführt werden, nicht aus Claude Code heraus.

----

===== Release erstellen =====

==== 1. Nach main mergen ====

Entweder selbst:
<code bash>
git checkout main
git merge dev
git push
</code>

Oder Claude Code sagen: //„merge nach main"//

''ci.yml'' läuft automatisch (Build + Test).

==== 2. Release-Tag setzen ====

<code bash>
git tag v1.2.3
git push --tags
</code>

''release.yml'' startet automatisch und erstellt einen Forgejo-Release mit ZIP-Anhang.
